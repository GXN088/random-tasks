Создадим тему GameConfig, которая использует статические блоки для инициализации игровых настроек при первой загрузке класса. Это идеально подходит для конфигурации, которую необходимо вычислить или настроить один раз перед созданием каких-либо игровых объектов.Давайте создадим систему GameConfigВы создадите два файла для организации вашего кода:: Создайте класс конфигурации, который инициализирует свои настройки с помощью статических блоков:GameConfig.javaПриватный статический массив  (int[]), в котором хранится количество очков, необходимое для достижения каждого уровняlevelThresholdsПриватная статическая переменная  (int), хранящая общее количество уровнейmaxLevelПриватная статическая переменная  (boolean) для отслеживания того, произошла ли инициализацияconfigLoadedИспользуйте статический блок для инициализации  значением 5 и выведите maxLevel"Initializing game configuration..."Используйте второй статический блок для создания массива  размером, равным levelThresholds, затем заполните его так, чтобы для каждого уровня требовалось maxLevel очков (для уровня 1 нужно 100, для уровня 2 — 200 и т. д.), и установите level * 100configLoaded в значение trueСтатический метод , который возвращает порог очков для этого уровня (уровни начинаются с 1)getThreshold(int level)Статический метод , который возвращает максимальный уровеньgetMaxLevel()Статический метод , который возвращает информацию о том, была ли загружена конфигурацияisConfigLoaded(): Продемонстрируйте, что статические блоки запускаются автоматически при обращении к классу. Вы получите один входной параметр: номер уровня для запроса. Выведите четыре строки:Main.javaConfig loaded: true или Config loaded: falseMax level: [maxLevel]Level [level] threshold: [threshold] (всегда показывайте также уровень 1)Level 1 threshold: [threshold]Вы получите один входной параметр: номер уровня (int) для запроса.Обратите внимание, как сообщение об инициализации выводится перед выполнением любого кода в Main — это статический блок выполняется при первой загрузке класса!
